Automatic editing detaches and a separate baseline monitors target/manual/focus/lock changes. Missing gap coverage keeps the full WAV. Recovery is single-flight, session scoped, and cannot restart the mic. Failed recovery keeps the original source. Pending retention 24 hours.

## First-APK limits / unverified gates

- Device validation is still required for Android background microphone start from accessibility overlay with activity closed and no warm microphone; selected keyboard retention; accessible full readback/selection and initial composing behavior; folded/unfolded/IME coordinates; stop/drain and actual provider commit timing; mic/service loss; long continuous speech and connectivity gaps. A compiled APK proves none of those runtime conditions.
- The current native transcription SDP exchange is documented/planned but has not been paid-tested with a real phone/account. Safe diagnostic status is available to investigate provider schema/model access.
- Reconnection preserves audio and retries transport, but it does not replay gap PCM live or continue in-field editing across the gap. Full recording is recovered after stop and labelled as a separately preserved/manual-copy result. Recovery performs recognition only, without the live correction pass. Chunked file upload follows provider size limits, but chunk boundaries may affect recognition; no overlap/deduplication pass is claimed.
- Nonempty unknown composing state and truncated/inconsistent field readback cause refusal, preserving existing text rather than promising universal editors. Full surrounding readback request is 100000 characters in each direction: this is an editor evidence limit, not a speech word quota; larger fields are refused if incomplete. Text/archive data grows with actual session/history; audio/frame queues are bounded.
- Bundled alien variants/local image import, edge snap, text+completed-audio history, pending-retention choices beyond24hours, usage/cost estimate screen, per-entry restore/compare action, and seamless live gap replay are not implemented. Their absence is explained in the app; no unsupported switches are present. Hold mode retains short-tap accessibility start/stop and main-screen cancel; long press invokes hold rather than the idle overlay menu in that mode.
- JSON/SharedPreferences/AtomicFile storage substitutes for planned Room/DataStore. API keys remain encrypted; text/audio are private app storage with backups disabled. Physical expiry happens when history/pending data is accessed rather than an always-running retention job.
- B self-correction acceptance intentionally skips ambiguous numeric/self-correction language. C's deterministic protected-token checks cannot prove semantic equivalence; the rewrite prompt plus conservative checks are safeguards, not a universal semantic guarantee.
