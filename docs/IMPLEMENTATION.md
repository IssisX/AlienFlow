## Observed failures and supported mechanisms

Owner reports malformed prompt-like text appearing inside the target field immediately after starting; clearing cache does not help. Supplied screenshot shows AF-E01 over the selected ChatGPT composer, with a cursor and keyboard visible. The screenshot also contains the malformed phrase in a keyboard clipboard chip; the owner separately confirms it appears inside the field. No full diagnostic export or physical reproduction is available. The exact source of that phrase remains unverified.

Rivals: stale recognition/provider events, existing result display, placeholder/label contamination, and editor focus discovery. Inspection finds no client literal or startup transcript injection. Recognition rendering uses provider events; the malformed phrase’s exact provider provenance cannot be excluded from the screenshot alone. The initial native regression run also establishes that empty EditText nodes advertise SET_TEXT but omit SET_SELECTION. The old capability gate required both and rejected such fields. The repaired empty-field action needs only SET_TEXT, whose result must include its documented cursor-at-end; it sends no separate cursor command. A source-supported introduced defect is established: 0.1.13 chooses ACTION_SET_TEXT for arbitrary existing fields and constructs its whole-field payload using accessibility text. A misreported placeholder can become a false prefix/suffix; this also contradicts the existing product contract against rebuilding unrelated fields. Native-widget/bridge regressions must distinguish placeholder metadata from independent keyboard contents and preserve actual typed text that equals a hint.

AF-E01 is the focus resolver’s rejection before microphone/provider startup. The previous resolver samples only service.findFocus(FOCUS_INPUT). The AndroidX Compose implementation initializes its virtual focus ID as invalid and populates it while materializing a node with isFocused=true; findFocus(FOCUS_INPUT) may therefore return null until the node is materialized. The precise installed ChatGPT implementation is unknown, but this demonstrates a shared virtual-editor discovery gap, not a need for an app-name allowlist.

## Implemented repair

The existing EditorBridge remains the sole writer. Node text actions are restricted to sessions beginning in an unambiguously empty field, where all later text belongs to dictation. Existing drafts use verified keyboard range edits, preserving prefix/suffix and selections; lack of a usable range connection fails without reconstructing the field. No mutation is resent or switched to another writer after dispatch. The whole-field ownership condition is derived from the captured initial snapshot and anchors, not inferred from current text or an app name.

Explicit hint metadata plus independently empty, complete keyboard contents can disambiguate a missing showing-hint flag. Hint-like words alone never authorize stripping text. Real entered text that happens to equal a hint remains user content. Ambiguous hints without independent evidence are refused. The first confirmed keyboard read is reused, followed by a fresh node comparison before dispatch. Surrounding-text requests cover the actual observed/proposed field lengths rather than requesting 100,000 characters in either direction. The read/confirmation deadline permits the platform’s documented couple-of-seconds IPC response, while the first matching observation succeeds immediately. Missing text plus an unknown cursor is not enough for the empty-field node action. No extra timer or server change precedes microphone capture.

Focus resolution keeps the direct system input-focus route as its fast path. When absent/noneditable, it traverses only the uniquely input-focused TYPE_APPLICATION window, requiring a unique visible/enabled input-focused eligible node. It does not use the touched active window, keyboard, accessibility overlay, arbitrary editable fields or stored terminal binding. Password candidates, ambiguous candidates and incomplete traversal are rejected. Traversal is bounded at 256 distinct nodes. XML enables inclusion of otherwise omitted semantics views and view IDs. Small diagnostic counters record resolution route, visited/candidate counts and traversal exhaustion, never field text or package names. Existing no-new-target adoption during capture remains.

The approved silver interface, pinned live preview, preference keys/defaults, keyboard choice, overlay focus flags, existing startup audio FIFO/minimal delay, light haptics, terminal final insertion and never-submit behavior are preserved. No cosmetic redesign is bundled with this failure repair.
