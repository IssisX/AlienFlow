## Implemented presentation

A native Home / History / Settings navigation bar stays available. Home contains a setup shortcut when needed, an actual dictation test field, coordinator status and a three-line latest-result preview. Full latest text has its own page. Settings is a six-category directory: Floating alien, Dictation & writing, Language & vocabulary, Privacy & saving, Account & setup, Help & about. Controls keep the existing preference keys/defaults and coordinator actions. Changes save automatically; ordinary preferences apply to the next session, appearance immediately. Language has named selections plus an explicit custom-code route. Vocabulary is limited to the existing 4,000-character guidance capacity and saved as typed. Troubleshooting/error-overlay control and diagnostics are under Help; account/permissions are under Setup.

History uses a native recycled ListView with two-line previews, dates and search over retained original/result text. Full text, copying, optional original comparison, status details and confirmed deletion have a separate transcript page. Recovery is a separate history subpage and preserves existing coordinator ownership, 24-hour retention, upload and no-new-field-insertion behavior. Clear-all, individual deletion, recording discard and key removal ask for confirmation inside the app. The existing JSON history storage still loads retained entries into memory; this is recycled view loading, not a paged database migration.

Presentation uses a dark charcoal palette, silver-blue accent, native controls with 48dp or larger touch targets, dp/sp sizing, readable spacing and a centered maximum 720dp reading width. Scrollable category pages support narrow windows and large fonts. System-bar, cutout and IME insets protect navigation and editable fields. The platform Back callback and in-app back button return to the actual entry page. Home draft, search, navigation stack and page scroll positions survive activity recreation. An unsaved API key is excluded from instance-state/autofill. The floating alien menu opens Settings directly, reusing an existing activity when possible. Accepted launcher/overlay artwork is unchanged.

Primary Android references: [View insets](https://developer.android.com/develop/ui/views/layout/edge-to-edge), [Back navigation](https://developer.android.com/guide/navigation/custom-back). No UI layer owns a second dictation or editor state machine.

## Owner follow-up: cold normal fields, sync failures, live appearance preview

Owner reports that 0.1.12 needs a Termux session before ordinary fields work, then reports Editor sync timed out; ChatGPT Android does not work. Precise phone state remains unknown without a fresh report. Rivals considered: retained terminal-mode state, unavailable/late accessibility IME attachment or surrounding-text support, inaccessible/custom composer semantics. Existing start/finish callbacks already clear terminal mode, while source decisively requires a keyboard connection and a non-null matching surrounding-text read for all ordinary fields. Android explicitly permits that read to return null when unsupported and warns of slow IPC. Thus a field with valid standard accessibility text/selection actions is unnecessarily refused or timed out by the existing mandatory route; this is a demonstrated capability limitation, not proof of the exact installed ChatGPT failure.

Normal fields advertising both SET_TEXT and SET_SELECTION now choose the accessibility-action route before any mutation. The same bridge uses its captured full text, cursor, prefix/suffix and generation, refreshes the same focused node, verifies every result, and never switches writers or resends uncertain text after dispatch. Fields without these actions keep the existing corroborated IME route; Termux keeps its single final commit. Unrelated/absent IME metadata no longer blocks node-capable fields or marks another app’s node protected. Protected nodes remain excluded. Same-editor restarting callbacks preserve identity only when the refreshed captured node still has focus and matches the editor’s package; content/cursor checks still revoke user changes. New sessions/finish invalidate ownership normally. No app-name rule, automatic submission, clipboard injection or active-window fallback was added. Installed ChatGPT capability remains unverified.

Floating alien has an embedded live preview of the actual approved artwork at the stored dp diameter/idle and active alpha, on light/dark backgrounds. Appearance slider changes redraw it immediately. The preview stays pinned above the scrolling controls, including on the narrow large-font layout. Preview readiness dots are clearly labelled as a recording appearance preview, not real microphone/provider readiness. The main theme now uses charcoal/slate/silver-blue colors matching the accepted icon. A short platform haptic tick marks the real mic-ready transition and finishing, respecting Android haptic settings. Existing startup audio buffering, capture concurrency and indicator authority remain.
